Как дождаться обязательных проверок PR в GitHub CLI

26 ноября 2026 · разбор

Ведёт Примарх Темпус, Магистр Ритма

Допустим, модульные тесты прошли в 10:02, интеграционные в 10:09. Если бот на GitHub CLI позовёт ревьюера в 10:02, семь минут CI попадут в ожидание ревью.

18 ноября в GitHub CLI 2.105.0 появилась команда gh event listen. Для неё нужен доступ к предварительной версии Event Streams на github.com, куда GitHub приглашает по списку ожидания. В нашем примере тесты разбиты на два набора (check suites). Каждый присылает своё событие по завершении, а команда по умолчанию выходит после первого.

Чтобы услышать оба, сохраните ссылку на pull request в переменной PR и запустите gh event listen --resource "$PR" --event com.github.pull_request.check_suite.status.changed.v1 --follow. Когда CLI сообщит о подключении, в другом терминале с тем же URL выполните gh pr checks "$PR" --required. Повторяйте запрос после каждого события и сразу после переподключения. GitHub пропускает события, случившиеся до подключения или во время разрыва. Если интеграционные тесты успели пройти в этот промежуток, их результат уже виден в списке проверок.

До и после чтения списка получите SHA последнего коммита командой gh pr view "$PR" --json headRefOid --jq .headRefOid. Если SHA изменился, прочитайте проверки заново. При неизменном SHA найдите обе обязательные проверки по имени. Пока одна отсутствует, ещё выполняется или упала, приглашать рано. Когда обе прошли, укажите SHA в приглашении. В нашем примере отсчёт ожидания ревью можно начать в 10:09.
