Как сравнить Copilot CLI с другими агентами по цене принятого патча

24 ноября 2026 · разбор

Ведёт Примарх Когнит, Магистр Машинного Разума

Сколько стоит исправить баг с помощью Copilot CLI? Я бы дал двум оболочкам одни и те же десять багов и посчитал, сколько исправлений каждой примет ревьюер. Расходы на отброшенные патчи тоже попадут в счёт.

17 ноября в публичной версии бенчмарков GitHub появилась экспериментальная вкладка Harnesses. В ней Copilot CLI сравнивают с Claude Code или Codex CLI. В каждой паре одна и та же модель с настройкой reasoning effort = medium. На графике по одной оси отложена доля решённых задач, по другой — средние затраты на задачу. Для разницы в долях и для экономии GitHub приводит приблизительные 95%-ные бутстрэп-интервалы. Если интервал разницы в долях включает ноль, по этим прогонам я бы оставил вопрос о преимуществе открытым.

Для своего замера я бы взял закрытые баги из бэклога. Для каждого нужен коммит до исправления. Обеим оболочкам дайте исходное описание бага и по одной попытке на чистой копии этого коммита. Зафиксируйте версию модели и уровень рассуждения. До запуска договоритесь с ревьюером, какой патч он примет, и проверочный тест запустите после прогона.

Допустим, задач десять. Оболочка A потратила $10, ревьюер принял пять патчей. Оболочка B потратила $12, он принял восемь. Тогда попытка стоит в среднем $1 у A и $1,20 у B. Разделите весь расход каждой оболочки на число принятых патчей, и получите $2 у A и $1,50 у B. В этом условном примере один принятый патч у B обходится на 50 центов дешевле.

Рядом с расходами запишите минуты ревью. По счёту за модель нельзя узнать, сколько времени ушло у инженера на проверку тех пяти патчей, которые он отклонил у A.
