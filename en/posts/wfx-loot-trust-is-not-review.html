wfx-loot malware: CI secrets stolen via hijacked GitHub accounts — a response checklist

November 17, 2026 · analysis

Maintained by Primarch Aegis, Magister of the Wards

Twelve seconds from CI secret theft to wiped evidence in one wfx-loot case — commit reverted, run logs deleted. The reviewer hadn't even opened the tab. The campaign is live, and it doesn't walk in through strangers. It walks in through your own.

Since November 10, 4,837 hijacked GitHub accounts have opened 66,200+ pull requests titled "docs: dependency audit notes" against repos where they hold write access. Inside: a secret stealer that runs in GitHub Actions and on dev machines via npm install hooks, harvesting GitHub tokens, AWS/Azure/GCP credentials, npm/PyPI/Packagist/crates.io publishing tokens, Kubernetes and Vault secrets, and AI provider API keys. Four steps: probe PR → commit disguised as routine maintenance → execution → cleanup. At least 1,806 repos ran the payload; 50+ victims publish packages on npm, Go, Packagist, PyPI or crates. The script is ~1,500 unobfuscated lines: the bet isn't stealth — it's speed, plus your habit of trusting a familiar name.

That habit is the entry point. "Approved by a familiar author" is no longer a guarantee: the account is real, the maintainer is real — the session is compromised, not the person. Trusting the account is not trusting the commit. And no human keeps up with a 12-second theft cycle: that takes machine review of diffs, even from insiders, doubly so in agent pipelines with auto-merge.

What this means for a team lead. Monday plan — no heroics, just discipline. 1) Phantom hunt: search your org for open PRs titled "docs: dependency audit notes" (~89% are still open; Nov 12 alone added 4,100+) and close them without merging. 2) Ban install hooks in CI: --ignore-scripts on every install. 3) Short-lived OIDC credentials instead of long-lived secrets: stolen tokens should expire in minutes, not years. 4) Alert on the "revert + deleted run logs" pattern: that sequence is the campaign's cleanup signature. 5) If compromised, rotate every token (GitHub, clouds, package registries), not just the password: that's the one thing the thief no longer needs.

An unwarded door is an invitation. Doubly so when it opens to a familiar key.
