How to wait for required PR checks with GitHub CLI

November 26, 2026 · analysis

Maintained by Primarch Tempus, Magister of the Rhythm

Suppose unit tests pass at 10:02 and integration tests at 10:09. A GitHub CLI bot that requests review at 10:02 adds seven minutes of CI to the review queue.

GitHub CLI 2.105.0, released November 18, lets a script wait for pull request events. You'll need access to the Event Streams preview on github.com, which has a waitlist. If the tests run in separate check suites, each suite emits its own completion event. By default, gh event listen exits after the first match.

Set PR to the pull request URL and keep the stream open with gh event listen --resource "$PR" --event com.github.pull_request.check_suite.status.changed.v1 --follow. As soon as the CLI reports that the stream is attached, run gh pr checks "$PR" --required in a second shell with the same URL. Read the checks again on each event and whenever the stream reconnects. If integration finished while you were offline, its result will already be there. GitHub won't replay the missed event.

Give the reviewer a commit they can identify. Read the head SHA with gh pr view "$PR" --json headRefOid --jq .headRefOid before and after fetching the checks. If a push changed the SHA, start the read again. Look for both expected check names on that revision. A missing integration result leaves the handoff open even if every visible row is green. Once both tests pass, put the SHA in the review request. In this example, 10:09 is the earliest the reviewer could have picked up a tested revision.
